# 已知待辦

此處記錄可經由目前程式碼或測試案例證實、但尚未於現有版本解決之技術債、工程缺口與重啟評估條件。清單內容並非即期交付之功能承諾；相關問題獲得修復後，負責該項變更的維護者應主動更新或移除對應項目，避免文件殘留過時資訊。

## 本機狀態與原子寫入

- 匯入流程中仍有少數鎖定檔更新操作採用標準檔案寫入。後續若重構此處流程，應全面改用共用之原子寫入機制，並補足寫入中途遭中斷之復原測試。
- 執行快取清理時，若某特定項目缺乏確定之現用版本、但存在多個候選快取目錄，ccync 會選擇全數保留並提出警示。若未來擬實作自動挑選清理機制，必須具備可驗證之所有權與版本證明，絕不可僅憑檔案修改時間逕行判斷。
- 身分重新綁定仍列為待辦。若管理器能證明套件身分變更後仍對應至原先受管理的安裝，且不會接管使用者自行管理的安裝，即可重新評估此項工作。
- 跨程序保存已載入的工具世代仍列為待辦。若支援的操作需要在程序重新啟動後偵測或復原世代變更，即可重新評估。
- `ccync upgrade tool:<id>` 維持 beta，所有套件更新關卡皆為 `Gated`。只有真機驗收通過後才應重新開啟。2026-10-01 的 Windows 驗收留下三個未結問題：已提交的 `tool refresh --json` 與 `upgrade --json` 會在 JSON 文件之前於 stdout 印出投影說明文字；兩次 `upgrade tool:rtk` 皆以管理器結束代碼 `101` 結束，原因未確認，且升級路徑會丟棄管理器的 stderr；復原只用注入的日誌演練過。

## 投影與主機行為

- OpenCode 設定檔路徑之環境變數覆寫機制，過往曾在實機測試中發生環境隔離失效問題。若修正此處邏輯，相關驗收測試絕不可觸及或汙染操作者的真實家目錄。
- 第三方上游安裝程式可能順著 Antigravity 之 junction 連結，直接改寫 ccync 所建置的輸出目錄。在推動改善方案前，須先行決策是由 ccync 主動防護輸出根目錄，抑或由安裝程式之包裝腳本限定僅向單一主要來源寫入。
- 目前兩階段投影僅於首次遭遇失敗時退回實體目錄複本。若未來改為持續重試符號連結，仍必須依循先建立暫存目錄再執行原子交換之原則，絕不可預先移除目前正常運作中的根目錄。
- 啟動時解析的 MCP 套件參照由 `feat-mcp-first-class-intake` 負責。該功能定義 MCP 套件參照在啟動時的解析方式，以及所有權與機密邊界後，即可重新評估此項工作。

## MCP 與發行管線

- MCP `--dry-run` 報告可進一步細化逐主機、逐伺服器的預覽明細。未來擴充功能時，若存在尚未解析之機密值或主機設定檔無法讀取，絕不可將該項目誤計入整體成功統計中。
- 發行檢查高度依賴執行平台與環境。若缺乏適用的 CI runner，對應之驗證檢查必須明確標註為 `NotRun`，不可擅自推論驗證合格。針對 Windows static CRT 靜態連結之相依性檢查，屬於不可退讓之必要門檻。
- 本次文件搬移未執行快照掃描器的 Unix 測試與非 Windows 正式程式碼分支。完成跨平台驗證前，仍須使用 Unix CI runner 或 WSL 實際測試。
- WinGet 遠端更新探索仍列為待辦。若 ccync 必須從遠端 WinGet 來源探索更新，而非取決於本機套件狀態，即可重新評估此項工作。
- 非 Windows 平台的 pipx 與 Homebrew Phase B 證明仍列為待辦。尚未證明的 Phase B 門檻維持 `gated`。備妥適用的非 Windows runner 後，再測試兩種套件管理器。測試範圍包括安裝、更新與復原。完成測試後，即可重新評估證明工作。
- 核准能力範圍以外的其他生命週期工作仍列為待辦。只有在受支援的平台、套件管理器或使用者流程有此需求，且所有權、復原與機密處理均可驗證時，才重新評估。最終驗收收據會列出目前門檻狀態；本文件不重複可能過時的門檻清單。

修改上述任一行為時，請同步更新負責規範該主題的核心文件：[設定與診斷](setup.zh-Hant.md)、[架構](architecture.zh-Hant.md)、[MCP](mcp.zh-Hant.md) 或 [指令參考](commands.zh-Hant.md)。
